# Drip Note 要求定義 v0.2

## 1. コンセプト
**記録したレシピを、タイマーとしてわかりやすく実行できること。**

ハンドドリップのレシピをステップ単位で記録し、抽出中は「今なにをするか」「次はいつ、どれだけ注ぐか」をひと目でわかるように案内する。抽出の結果（味の評価）を残し、レシピの改善に役立てる。

## 2. 想定ユーザー
| フェーズ | ユーザー | 重視すること |
|---|---|---|
| MVP | 自分（個人） | 毎朝ストレスなく使えること |
| 将来 | 一般のハンドドリップ愛好家 | わかりやすさ、プリセットのレシピ |
| 将来 | バリスタ（練習用） | 再現性、記録の分析、レシピ共有 |

MVPは個人用に絞る。ただし将来の拡張を見越して、データモデルは共有やエクスポートがしやすい形にしておく。

## 3. MVPの機能要求

### F1. レシピ管理
- レシピの作成・編集・複製・削除・一覧表示
- 基本パラメータ：名前、器具（V60など）、豆の量(g)、湯量(g)、湯温(℃)、挽き目、メモ
- 比率（例 1:15）を自動で表示する
- ステップ
  - 項目：**開始時刻**（抽出開始からの経過時間）、種類（蒸らし／注湯／待機／完了など）、注湯量(g)、メモ
  - 累計湯量を自動で計算して表示する
  - 開始時刻の順に自動で並べる

例：
```
V60 4:6メソッド
豆 20g / 湯 300g / 93℃ / 中細挽き

0:00  蒸らし   50g  (計 50g)
0:45  2投目   70g  (計120g)
1:30  3投目   60g  (計180g)
2:10  4投目   60g  (計240g)
2:50  5投目   60g  (計300g)
3:30  完了
```

### F2. 抽出タイマー（最重要）
- レシピを選び、ワンタップでスタートできる
- 画面には次の内容を、大きな文字で見やすく表示する
  - 経過時間
  - 現在のステップ（種類、注湯量、目標の累計湯量）
  - 次のステップまでの残り時間と、次のステップの内容
  - 全体の進み具合（ステップの一覧またはプログレス）
- 開始時刻になったら、次のステップへ自動で進む
- 一時停止・再開・リセットができる
- 抽出中は画面がスリープしない
- 抽出中は手がふさがっている前提で、操作の数は最小限にする

### F3. バックグラウンド実行と Live Activity
- アプリがバックグラウンドに回っても、タイマーは止めずに続ける
- Live Activity（ロック画面と Dynamic Island）に次の内容を表示する
  - 経過時間
  - 現在のステップ、目標の累計湯量
  - 次のステップまでの残り時間
- Live Activity をタップするとタイマー画面に戻る
- 抽出が終わったら Live Activity も終了する

### F4. 音・振動での通知
- 次のステップの数秒前（例：3秒前）にカウントダウンで知らせる
- ステップが切り替わる瞬間に知らせる
- **マナーモード中は音を出さず、振動だけで知らせる**
- 設定で音のON/OFF、振動のON/OFFを切り替えられる
- バックグラウンド中も、ステップの切り替えを振動（と、マナーモードでなければ音）で知らせる

### F5. 抽出ログ・味の評価
- タイマーが終わったら、そのまま記録画面に移る
- 記録する内容
  - 日時
  - 使ったレシピ（その時点の内容をコピーして残す。あとでレシピを編集してもログは変わらない）
  - 実際の総抽出時間
  - 総合評価（★1〜5）
  - 味の評価項目ごとのスコア
  - 自由メモ
- **味の評価項目はユーザーが自由に作成・編集・並べ替えできる**（初期値の例：酸味、苦味、甘み、ボディ、後味）
- ログの一覧、レシピ別のログ表示
- ログの内容を元にレシピを修正できる導線をつける

## 4. 非機能要求
| 項目 | 要求 |
|---|---|
| プラットフォーム | iOS（SwiftUI）。SwiftData と最近の ActivityKit API を使うため iOS 17 以上 |
| データ保存 | SwiftData で端末内に保存する。将来 iCloud 同期（CloudKit）を足せるよう、モデルは CloudKit の制約に合わせる（全プロパティが Optional かデフォルト値あり、unique 制約なし） |
| タイマー精度 | 表示のずれは ±0.1秒以内。カウントを積み上げる方式はとらず、開始時刻（`Date`）との差分で計算する。バックグラウンドから戻ったときにも正しく復元できる |
| オフライン | ネットワークなしですべての機能が動く |
| 外観 | ダークモードに対応する（早朝の暗い部屋で使う想定） |
| 言語 | 日本語のみ |

## 5. MVPでやらないこと
- 豆の量を変えたときに、湯量やステップを比例して自動計算する機能（後で検討）
- iCloud 同期、アカウント、レシピ共有
- 豆の管理（銘柄・焙煎日）
- Apple Watch
- Bluetooth スケール連携（Acaia など）
- 多言語対応

## 6. 将来の構想
- レシピのスケーリング（豆の量に合わせて比例で再計算）
- 豆の管理と、ログとの紐付け
- レシピのエクスポート／インポート（JSON・QRコード）による、バリスタ同士の共有
- Apple Watch 対応
- ログの分析（評価の高い条件の傾向など）
- プリセットのレシピ（4:6メソッドなど）
- iCloud 同期

## 7. 技術的なリスクと確認事項
iOS の制約上、設計の前に検証（スパイク）が必要な点。

1. **バックグラウンドでは、アプリのコードが動き続けられない**
   - iOS はバックグラウンドに回ったアプリをすぐに停止する。そのため、アプリ側のタイマーで「時刻になったら振動させる」ことはできない
   - 対応案：タイマーをスタートしたときに、各ステップの時刻に**ローカル通知を予約**しておく。通知は振動し、マナーモードでなければ音も鳴る。一時停止やリセットのときは予約を取り消して再登録する
   - 検証すること：通知がバナーで邪魔にならないか。Time Sensitive 通知を使うか
2. **Live Activity の表示を切り替えるタイミング**
   - 経過時間や残り時間は `Text(timerInterval:)` を使えば OS が自動でカウントするので、アプリが止まっていても進む
   - 一方で「現在のステップ」の文字を切り替えるには、Live Activity の更新が必要になる。バックグラウンドで停止したアプリからは更新できない（サーバーからの Push 更新を使わない場合）
   - 検証すること：レシピの全ステップを Live Activity の状態にあらかじめ渡しておき、表示側で時刻に応じて切り替えられるか。無理なら「次のステップまでの残り時間」だけをカウントし、ステップ名の切り替えは通知に任せる案にする
3. **マナーモードの判定**
   - アプリが前面にあるとき：システムサウンド（`AudioServicesPlaySystemSound`）を使う。システムサウンドはマナーモード中は自動で無音になる。振動はハプティクスで別に鳴らす（実装済み）
   - バックグラウンドのとき：ローカル通知は OS の設定に従う（マナーモード中は振動のみ）
